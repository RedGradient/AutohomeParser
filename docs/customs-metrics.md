# Метрики таможенных расчётов

Отчёт показывает размер автомобильного каталога, покрытие таможенными
расчётами и причины, из-за которых часть платежей рассчитать нельзя.

Метрики вычисляются заранее и сохраняются одной строкой в таблице
`customs_metrics`. Страница и API только читают этот снимок, поэтому их открытие
не запускает тяжёлую агрегацию по таблицам расчётов.

## Обновление снимка

В development-конфигурации:

```bash
make calculate-customs-metrics
```

В production без Makefile:

```bash
docker compose -f compose.prod.yaml run --rm metrics
```

Перед первым запуском должны быть применены миграции. Для содержательного
отчёта сначала рассчитайте таможенные платежи. Повторный запуск заменяет
предыдущий снимок; история метрик не хранится.

## Доступ

- HTML-отчёт: `/metrics/customs`;
- JSON API: `/api/v1/metrics/customs`.

Оба маршрута публичные. Если снимок ещё не создан, JSON API возвращает `404`, а
страница показывает предложение запустить расчёт метрик.

## Размер каталога

- `brands_count` — число брендов;
- `series_count` — число серий;
- `specs_count` — число комплектаций;
- `modifications_count` — число сформированных технических модификаций.

## Покрытие расчётами

Сценарий — расчёт одной комплектации для одного типа импортёра. Поэтому число
сценариев может быть больше числа комплектаций.

- `customs_scenarios_count` — все сохранённые сценарии;
- `complete_scenarios_count` — каждый ожидаемый платёж рассчитан либо помечен
  как неприменимый;
- `partial_scenarios_count` — сценарии, которые не попали в более точную
  категорию и не содержат полного набора результатов;
- `missing_data_scenarios_count` — не хватает исходных характеристик;
- `manual_review_scenarios_count` — требуется ручная классификация;
- `unsupported_scenarios_count` — текущие правила не поддерживают случай;
- `specs_with_complete_scenario_count` — комплектации хотя бы с одним полностью
  рассчитанным сценарием.

Статусы сценариев взаимоисключающие. При нескольких проблемах применяется
приоритет: `MISSING_DATA`, затем `MANUAL_REVIEW`, затем `UNSUPPORTED`, затем
`PARTIAL`.

## Причины MISSING_DATA

Объект `missing_data_statistics` содержит:

- число затронутых сценариев и комплектаций;
- распределение по типу импортёра и виду платежа;
- частоту отсутствующих и некорректных исходных полей;
- причины, записанные калькулятором;
- сочетания вида платежа и отсутствующего поля.

Эти показатели помогают отличить единичные ошибки данных от систематически
отсутствующей характеристики, которую стоит добавить в нормализацию парсера.

## Актуальность

Поле `generated_at` показывает время формирования снимка в UTC; HTML-страница
отображает его по московскому времени. Версия формата находится в
`schema_version`. Метрики не обновляются автоматически вместе с каждым ответом
парсера или API — после изменения исходных данных нужно снова запустить команду
обновления.
