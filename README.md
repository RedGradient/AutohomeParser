# Парсер Autohome

Scrapy-паук получает данные из JSON-эндпоинтов Autohome, нормализует их и
сохраняет через SQLAlchemy в PostgreSQL или SQLite.

Для первоначальной загрузки `treeMenu` необходима системная команда `curl`.
Этот ответ CDN Autohome не всегда корректно завершается в браузерах и загрузчике
Twisted, который использует Scrapy. Полученный ответ кешируется в
`data/tree_menu.json`; остальные запросы выполняются средствами Scrapy.

## Установка и запуск

```bash
python -m pip install -r requirements.txt
scrapy crawl cars
```

Ограниченная проверка каталога:

```bash
scrapy crawl cars -a max_series=10 -a max_config_requests_per_series=1
```

Проверка одной серии:

```bash
scrapy crawl cars -a series_id=18 -a city_id=110100
```

Быстрая проверка с двумя запросами полных конфигураций:

```bash
scrapy crawl cars -a series_id=18 -a max_config_requests_per_series=2
```

Дозагрузка отсутствующих полных конфигураций после прерванного обхода:

```bash
scrapy crawl cars -a resume_configs=1
```

Проверка режима дозагрузки максимум на 20 комплектациях:

```bash
scrapy crawl cars -a resume_configs=1 -a max_resume_specs=20
```

Режим дозагрузки не обращается к эндпоинтам каталога и списков серий. Он
выбирает поддерживающие полную конфигурацию комплектации, для которых в таблице
`spec_parameters` ещё нет записей.

## Многопроцессный запуск

Перед запуском двух сетевых интерфейсов включите временную маршрутизацию и
проверьте внешние IP:

```bash
make network-up
make network-test
```

Запустите по одному процессу Scrapy на Wi-Fi и Ethernet:

```bash
.venv/bin/python run_multi.py \
  --interfaces wlp0s20f3,enp0s20f0u1c4i2
```

Каждый процесс привязывает запросы к IPv4-адресу своего интерфейса. Серии
распределяются между процессами по остатку от деления идентификатора серии на
количество процессов, поэтому разные процессы не скачивают одну серию.
Строки журнала каждого процесса имеют собственный цвет и начинаются с имени
соответствующего сетевого интерфейса.

Перед запуском мастер-процесс разрешает IPv4-адреса доменов Autohome и проверяет
доступность HTTPS через каждый исходный IP. DNS-кеш Scrapy отключён: повторные
попытки снова разрешают имя и не закрепляют неработающий адрес CDN на весь
период обхода. Только для диагностики проверку можно пропустить аргументом
`--skip-dns-check`.

Без `DATABASE_URL` процессы записывают результаты в отдельные SQLite-файлы:

```text
data/workers/autohome_wlp0s20f3.sqlite3
data/workers/autohome_enp0s20f0u1c4i2.sqlite3
```

Если передан PostgreSQL URL, оба процесса параллельно записывают данные в одну
общую базу. Серии распределены между workers, а повторяющиеся родительские
записи безопасно обновляются через `INSERT ... ON CONFLICT DO UPDATE`.

Ограниченная проверка многопроцессного режима:

```bash
.venv/bin/python run_multi.py \
  --interfaces wlp0s20f3,enp0s20f0u1c4i2 \
  --max-series 2
```

После завершения или перед отключением одной из сетей удалите временные правила:

```bash
make network-down
```

Первый `Ctrl+C` запускает штатное завершение Scrapy: мастер ожидает до 60 секунд,
пока workers закроют пауков и запишут буферы в базы. Повторный `Ctrl+C` завершает
оставшиеся процессы принудительно. Таймаут можно изменить, например:

```bash
.venv/bin/python run_multi.py \
  --interfaces wlp0s20f3,enp0s20f0u1c4i2 \
  --shutdown-timeout 120
```

## PostgreSQL в Docker

Создайте локальный файл окружения и задайте пароль PostgreSQL:

```bash
cp .env.example .env
```

Запустите PostgreSQL в Docker:

```bash
make postgres-up
```

Парсер остаётся локальной консольной утилитой. Перед полным обходом настройте
маршруты и запустите его из виртуального окружения:

```bash
make network-up
make network-test
make parser-run
```

Команда `make parser-run` запускает локальный `run_multi.py`. Оба Scrapy-процесса
используют физические интерфейсы хоста и параллельно подключаются к PostgreSQL,
порт которого опубликован только на `127.0.0.1`.

Дозагрузка отсутствующих конфигураций:

```bash
make parser-resume
```

Остановка сервисов без удаления данных PostgreSQL:

```bash
make docker-down
make network-down
```

В Docker работает только PostgreSQL. Именованный volume `postgres_data`
сохраняется после `docker compose down`. Его удаление командой
`docker compose down -v` необратимо удалит базу.

При обычном однопроцессном запуске без `DATABASE_URL` база создаётся в
`data/autohome.sqlite3`.

## Таблицы

- `brands` — бренды;
- `series` — серии автомобилей;
- `specs` — конкретные комплектации;
- `parameter_definitions` — определения технических характеристик;
- `spec_parameters` — значения характеристик комплектаций.

Поле `spec_parameters.title_id` ссылается на
`parameter_definitions.title_id`. Обозначения Autohome сохраняются без
изменений: `●` означает штатное оснащение, `○` — опцию, а `-` — отсутствие
оборудования.

## Локальный словарь

Файл `autohome/data/translations_ru.json` содержит русские переводы названий
характеристик, типовых значений и повторяющихся фрагментов названий
комплектаций. Если перевода нет, исходный китайский текст должен сохраняться
без изменений.

Pipeline применяет словарь ко всем новым нормализованным данным. Исходный
`raw_json` остаётся китайским. Числа с единицами `万`, `万元`, `万公里` и `亿`
нормализуются программно, например `14.18万` превращается в `141800`.

Для перевода данных, сохранённых до подключения словаря, сначала остановите
парсер, затем выполните:

```bash
make translate-db
```

Команда изменяет существующие нормализованные поля пакетами. Неизвестные строки
остаются без изменений.
