# Парсер Autohome

Scrapy-паук получает данные из JSON-эндпоинтов Autohome, нормализует их и
сохраняет через SQLAlchemy в PostgreSQL.

Для первоначальной загрузки `treeMenu` необходима системная команда `curl`.
Этот ответ CDN Autohome не всегда корректно завершается в браузерах и загрузчике
Twisted, который использует Scrapy. Полученный ответ кешируется в
`data/tree_menu.json`; остальные запросы выполняются средствами Scrapy.

## Установка и запуск

```bash
python -m pip install -r requirements.txt
scrapy crawl cars
```

## HTTP API и Swagger

API читает ту же базу, что и парсер. Адрес берётся из `DATABASE_URL`; без
переменной используется локальный PostgreSQL на `127.0.0.1:5432`. Все прикладные эндпоинты,
кроме минимального `/health`, требуют JWT. Перед запуском задайте собственные учётные
данные и секрет подписи длиной не менее 32 байт:

```bash
export API_USERNAME=autohome
export API_PASSWORD='сложный-пароль'
export API_JWT_SECRET="$(openssl rand -hex 32)"
export API_JWT_TTL_SECONDS=3600
uvicorn autohome.api.app:create_app --factory --host 0.0.0.0 --port 8000
```

Получение токена:

```bash
curl -X POST http://localhost:8000/api/v1/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"username":"autohome","password":"сложный-пароль"}'
```

Полученный `access_token` передаётся как `Authorization: Bearer <token>`.
В Swagger UI токен можно ввести через кнопку **Authorize**. Страницы
документации, схема OpenAPI и эндпоинт выдачи токена остаются публичными.

После запуска доступны:

- API: `http://localhost:8000/api/v1`;
- Swagger UI: `http://localhost:8000/docs`;
- ReDoc: `http://localhost:8000/redoc`;
- OpenAPI JSON: `http://localhost:8000/openapi.json`.

OpenAPI формируется автоматически из документированных Pydantic-схем в
`autohome/api/schemas.py`, поэтому описание API всегда соответствует коду.

### Запуск в Docker

API, парсер и PostgreSQL запускаются в Docker. Скопируйте пример настроек,
замените пароль и JWT-секрет, а также проверьте имена сетевых интерфейсов:

```bash
cp .env.example .env
make api-up
```

Команда собирает образ приложения, ожидает готовности PostgreSQL и запускает
API на `http://127.0.0.1:8000`, Redis, Celery worker и Celery beat. Production
Compose публикует только nginx, а контейнер API доступен лишь во внутренней
Docker-сети. Просмотр логов и остановка:

```bash
make api-logs
make celery-logs
make docker-down
```

Для production используется отдельная конфигурация:

```bash
make COMPOSE_FILE=compose.prod.yaml api-up
```

Парсер использует сетевой стек хоста, поэтому видит физические Wi-Fi и Ethernet
интерфейсы и использует временные правила маршрутизации, созданные командой
`make network-up`. Каталог `data/` подключается в контейнер и сохраняет кеш
каталога и состояние загрузки:

Имена интерфейсов зависят от компьютера. Посмотрите их командой:

```bash
ip -br link
```

Затем задайте их в `.env`. Например, имена `wlp0s20f3` и
`enp0s20f0u1c4i2` относятся только к одному из возможных вариантов
конфигурации ноутбука:

```dotenv
AUTOHOME_INTERFACES=wlp0s20f3,enp0s20f0u1c4i2
WIFI_IF=wlp0s20f3
ETH_IF=enp0s20f0u1c4i2
```

```bash
make network-up
make parser-run
# либо режим дозагрузки
make parser-resume
```

`Ctrl+C` передаётся контейнеру, а `stop_grace_period` совпадает с
`SHUTDOWN_TIMEOUT`, чтобы Scrapy успел штатно завершиться и записать буферы.
Локальный запуск API через `make api-run` сохранён для разработки.

Ограниченная проверка каталога:

```bash
scrapy crawl cars -a max_series=10 -a max_config_requests_per_series=1
```

При полном запуске паук также загружает шесть последних доступных месячных
рейтингов продаж серий и марок, а для каждой серии — фотографии всех основных
категорий и доступные фильтры цветов кузова и салона. Число месяцев можно
изменить:

```bash
scrapy crawl cars -a sales_months=12
```

Отключение дополнительных контуров, например для быстрой проверки
характеристик:

```bash
scrapy crawl cars -a parse_sales=0 -a parse_galleries=0
```

Проверка одной серии:

```bash
scrapy crawl cars -a series_id=18 -a city_id=110100
```

Быстрая проверка с двумя запросами полных конфигураций:

```bash
scrapy crawl cars -a series_id=18 -a max_config_requests_per_series=2
```

Дозагрузка отсутствующих полных конфигураций после прерванного обхода:

```bash
scrapy crawl cars -a resume_configs=1
```

Проверка режима дозагрузки максимум на 20 комплектациях:

```bash
scrapy crawl cars -a resume_configs=1 -a max_resume_specs=20
```

Режим дозагрузки не обращается к эндпоинтам каталога и списков серий. Он
выбирает поддерживающие полную конфигурацию комплектации, для которых в таблице
`spec_parameters` ещё нет записей.

## Многопроцессный запуск

Перед запуском двух сетевых интерфейсов включите временную маршрутизацию и
проверьте внешние IP:

```bash
make network-up
make network-test
```

Запустите по одному процессу Scrapy на Wi-Fi и Ethernet:

```bash
.venv/bin/python run_multi.py \
  --interfaces wlp0s20f3,enp0s20f0u1c4i2
```

Каждый процесс привязывает запросы к IPv4-адресу своего интерфейса. Серии
распределяются между процессами по остатку от деления идентификатора серии на
количество процессов, поэтому разные процессы не скачивают одну серию.
Строки журнала каждого процесса имеют собственный цвет и начинаются с имени
соответствующего сетевого интерфейса.

Перед запуском мастер-процесс разрешает IPv4-адреса доменов Autohome и проверяет
доступность HTTPS через каждый исходный IP. DNS-кеш Scrapy отключён: повторные
попытки снова разрешают имя и не закрепляют неработающий адрес CDN на весь
период обхода. Только для диагностики проверку можно пропустить аргументом
`--skip-dns-check`.

Оба процесса параллельно записывают данные в общую базу PostgreSQL, указанную
в `DATABASE_URL`. Серии распределены между workers, а повторяющиеся родительские
записи безопасно обновляются через `INSERT ... ON CONFLICT DO UPDATE`.

Ограниченная проверка многопроцессного режима:

```bash
.venv/bin/python run_multi.py \
  --interfaces wlp0s20f3,enp0s20f0u1c4i2 \
  --max-series 2
```

Для многопроцессного запуска доступны параметры `--sales-months`,
`--skip-sales`, `--skip-galleries` и `--gallery-categories`. Рейтинги загружает
только worker с индексом 0, а галереи распределяются между workers вместе с
сериями.

После завершения или перед отключением одной из сетей удалите временные правила:

```bash
make network-down
```

Первый `Ctrl+C` запускает штатное завершение Scrapy: мастер ожидает до 60 секунд,
пока workers закроют пауков и запишут буферы в базы. Повторный `Ctrl+C` завершает
оставшиеся процессы принудительно. Таймаут можно изменить, например:

```bash
.venv/bin/python run_multi.py \
  --interfaces wlp0s20f3,enp0s20f0u1c4i2 \
  --shutdown-timeout 120
```

## PostgreSQL в Docker

Создайте локальный файл окружения и задайте пароль PostgreSQL:

```bash
cp .env.example .env
```

Запустите PostgreSQL в Docker:

```bash
make postgres-up
```

Изменения структуры базы управляются Alembic. Миграции автоматически
применяются перед запуском API, Celery worker и парсера. Их также можно
запустить отдельно:

```bash
make database-migrate
```

Текущую ревизию можно проверить командой:

```bash
DATABASE_URL='postgresql+psycopg://...' .venv/bin/alembic current
```

Парсер остаётся локальной консольной утилитой. Перед полным обходом настройте
маршруты и запустите его из виртуального окружения:

```bash
make network-up
make network-test
make parser-run
```

Команда `make parser-run` запускает локальный `run_multi.py`. Оба Scrapy-процесса
используют физические интерфейсы хоста и параллельно подключаются к PostgreSQL,
порт которого опубликован только на `127.0.0.1`.

Дозагрузка отсутствующих конфигураций, месячных рейтингов и галерей:

```bash
make parser-resume
```

В этом режиме характеристики запрашиваются только для комплектаций без
сохранённых параметров. Рейтинги обновляются за заданное количество месяцев, а
галереи серий повторно обходятся с `UPSERT`, поэтому уже сохранённые фотографии
не дублируются. Для временного пропуска галерей можно запустить `run_multi.py` с
аргументом `--skip-galleries`.

После изменения схемы характеристик можно очистить только связанные с ними
таблицы, сохранив каталог, продажи и фотографии:

```bash
make parameters-reset
make parser-resume
```

Первая команда безвозвратно удаляет ранее загруженные технические параметры.
Вторая заново поставит в очередь конфигурации всех комплектаций.

Остановка сервисов без удаления данных PostgreSQL:

```bash
make docker-down
make network-down
```

Именованный volume `postgres_data`
сохраняется после `docker compose down`. Его удаление командой
`docker compose down -v` необратимо удалит базу.

## Таблицы

- `brands` — марки автомобилей;
- `manufacturers` — производители и заводы;
- `brand_manufacturers` — связь марок с производителями;
- `series` — серии автомобилей;
- `specs` — конкретные комплектации;
- `parameter_groups` — группы технических характеристик;
- `parameter_sections` — разделы характеристик;
- `parameter_definitions` — определения характеристик;
- `spec_parameters` — значения характеристик комплектаций;
- `parameter_subitems` — вложенные варианты составных параметров;
- `parameter_color_sets` — наборы цветов кузова и салона;
- `parameter_colors` — отдельные цвета и их свойства;
- `spec_powertrains` — типизированные параметры силовой установки комплектации;
- `spec_vehicle_attributes` — нормализованные кузовные, массовые и
  классификационные признаки комплектации;
- `modifications` — технические модификации серии и модельного года;
- `series_monthly_sales` — продажи и позиции серий по месяцам;
- `brand_monthly_sales` — продажи и позиции марок по месяцам;
- `series_gallery_colors` — цвета кузова и салона в галереях серий;
- `series_photos` — фотографии серий, категории и прямые URL изображений;
- `series_photo_colors` — связь фотографий с цветами кузова и салона;
- `customs_calculations` — актуальный расчёт для комплектации и типа импортёра;
- `customs_payment_results` — суммы и детализация отдельных платежей.

Пара `(spec_id, parameter_id)` является первичным ключом `spec_parameters`.
`parameter_id` — устойчивый хеш исходного семантического пути
`groupname + itemtype + itemname`. Поле `title_id` применяется только временно,
чтобы связать определение и значение внутри одного ответа API, и сохраняется
только в исходном `raw_json`. Подэлементы и цвета ссылаются на параметр
составными внешними ключами и сохраняют порядок из ответа API. Вложенные
`sublist` и `colorinfo` дополнительно раскладываются по связанным таблицам.

Цены хранятся числом в юанях: `32.29万` записывается как `322900.00`.
Комплектации без положительной `guide_price_yuan` и `dealer_price_yuan`
отбрасываются до загрузки полной конфигурации и не сохраняются в каталоге.
Значения вложенных параметров оснащения нормализуются при записи: `●` означает
`true` (штатное оснащение), а `○` и `-` — `false` (опция либо отсутствие).
Исходный символ сохраняется в `raw_json` родительского параметра.

Нормализация силовой установки, кузовных и массовых характеристик выполняется
на лету при получении полного ответа конфигурации. Частичный ответ не
перезаписывает `spec_vehicle_attributes`. После изменения правил группировки
силовой установки доступна также контрольная идемпотентная команда полного
пересчёта:

```bash
make build-modifications
```

Команда заново строит `spec_powertrains` и `modifications`, после чего записывает
`specs.modification_id`. Комплектации с неполным техническим ключом намеренно не
объединяются между собой; причины сохраняются в `missing_fields_json`.

Нормализованные кузовные, массовые и классификационные признаки существующих
комплектаций пересчитываются той же функцией, которую вызывает паук:

```bash
make normalize-vehicle-attributes
```

Для проверки без записи можно запустить `normalize_vehicle_attributes.py` с
`--dry-run`. Команда также поддерживает диапазоны `spec_id`, `--only-outdated`
и независимые шарды через `--shard-index`/`--shard-count`.

Готовность нормализованных данных к безопасной классификации по товарным
позициям 8702, 8703 и 8704 проверяется без изменения БД:

```bash
make audit-vehicle-classifications
```

Классификатор использует версию правил
`RU-EAEU-VEHICLE-CLASSIFICATION-2026-10-20-v3` и не угадывает назначение
пикапов и фургонов по одному типу кузова. Пикапы проверяются по условиям Решения
КТС № 751; отсутствие числа осей блокирует только вывод 8703, но не мешает
доказать 8704 по массе, длине платформы или формуле грузовой составляющей.
Помимо `CLASSIFIED`, классификатор возвращает
`AMBIGUOUS`, `MISSING_DATA`, `MANUAL_REVIEW` или `UNSUPPORTED` с конкретной
причиной отказа.

При конфликте `body_type` и `vehicle_class` учитывается разная семантика полей:
тип кузова относится к конкретной комплектации, а класс может описывать всё
семейство модели. Грузовой кузов внутри класса фургона принимается для 8704
только при количестве мест менее 10; десятиместные варианты остаются на ручной
проверке. Для сочетаний грузовика и пикапа применяется более специфичная ветка
пикапа. Выбранное правило разрешения конфликта сохраняется в деталях.

Каталог косвенных признаков можно проверить на текущих сырых параметрах и
названиях без изменения базы:

```bash
make audit-indirect-vehicle-attributes
```

Команда выводит значения, сработавшие правила, уровень надёжности, конфликты и
остаток `true` / `false` / `NULL` для `is_special_purpose`. Для подтверждения
обычной перевозки она использует также нормализованные кузовные признаки, класс,
места, грузовой отсек и грузоподъёмность. Все такие решения получают метку
`INFERRED_INPUTS_USED` и версию набора правил.
Она различает нормализованный тип назначения автомобиля и признак позиции 8705:
скорая помощь, автодом и мусоровоз не становятся специальной техникой 8705.
Для грузовиков с отсутствующей полной массой правило сначала проверяет явное
обозначение массы шасси в названии (`4.5吨`, `6吨` и т. п.), затем может вывести
массу по формуле `curb_mass + payload + seats * 65`. Формула применяется только
к одиночным, непротиворечивым значениям и получает надёжность `MEDIUM` и метку
`INFERRED_INPUTS_USED`; прямая полная масса всегда имеет приоритет.

При обработке новой полной конфигурации парсер автоматически применяет те же
правила и записывает результат в `spec_vehicle_attributes`. Явное значение имеет
приоритет над косвенным; противоречие сохраняется в `warnings_json`. Для уже
загруженного каталога сначала выполняется безопасный dry-run:

```bash
make backfill-vehicle-attribute-inferences
```

Для записи проверенного результата:

```bash
make backfill-vehicle-attribute-inferences \
  BACKFILL_VEHICLE_ATTRIBUTE_INFERENCES_ARGS=--write
```

Команда поддерживает `--limit`, диапазон `--min-spec-id`/`--max-spec-id`,
`--shard-index`/`--shard-count` и `--only-outdated`. Записанные решения содержат
`rule_code`, доказательства, надёжность, версию правил и метку
`INFERRED_INPUTS_USED`. Эта же метка переносится в `warnings_json` таможенного
расчёта и в его снимок входных данных.

## Расчёт таможенных платежей

Поддерживаемые категории транспорта, обязательные данные и границы будущего
расширения на позиции 8702 и 8704 зафиксированы в
[`docs/import-duty-vehicle-scope.md`](docs/import-duty-vehicle-scope.md).
Найденные в `raw_json` косвенные признаки задних сидений, окон, задней двери,
грузового отсека и специального назначения описаны в
[`docs/indirect-vehicle-attributes-raw-audit.md`](docs/indirect-vehicle-attributes-raw-audit.md).

Для нормализованных автомобилей можно рассчитать поддерживаемые таможенные
платежи при импорте из Китая в Россию для физического и юридического лица:

```bash
make calculate-customs-payments
```

По умолчанию команда полностью обновляет текущие расчёты. Режим
`--mode stale` записывает только отсутствующие или изменившиеся сценарии:

```bash
make calculate-customs-payments \
  CALCULATE_CUSTOMS_PAYMENTS_ARGS="--mode stale"
```

Ежедневная задача Celery выполняет полный пересчёт после изменения курса ЦБ и
инкрементальный — при неизменном курсе. После успешного завершения
многопроцессного парсера инкрементальный пересчёт запускается автоматически.
Его можно отключить аргументом `--skip-customs-recalculation` утилиты
`run_multi.py`.

Аргументы команды можно передать через `CALCULATE_CUSTOMS_PAYMENTS_ARGS`, например
для полного проверочного запуска без записи:

```bash
make calculate-customs-payments \
  CALCULATE_CUSTOMS_PAYMENTS_ARGS="--date 2026-10-19 --dry-run"
```

Команда сначала использует каталожную цену `guide_price_yuan`, а при её
отсутствии — `dealer_price_yuan`. Если конкретная возрастная ставка зависит
только от объёма двигателя, отсутствие обеих цен не мешает расчёту и сохраняется
как `price_source = NOT_REQUIRED`. Официальные курсы CNY и EUR Банка России и
воспроизводимый снимок входных данных сохраняются в `customs_calculations`.
В `customs_payment_results` записываются отдельные результаты платежей:

- `IMPORT_DUTY` — ввозная пошлина;
- `CUSTOMS_FEE` — сбор за таможенные операции по шкале, действующей на дату расчёта;
- `RECYCLING_FEE` — утилизационный сбор;
- `EXCISE` — акциз для юридического лица;
- `VAT` — НДС для юридического лица.

Пока доставка, страхование и другие включаемые расходы не передаются в
калькулятор, таможенный сбор считается по цене автомобиля и получает
предупреждение `INCOMPLETE_CUSTOMS_VALUE`.

Проверка небольшой выборки без записи в базу:

```bash
DATABASE_URL="$DATABASE_URL" .venv/bin/python calculate_customs_payments.py \
  --date 2026-10-19 --limit 100 --dry-run
```

Расчёт носит оценочный характер: модельный год преобразуется в предполагаемую
дату выпуска 1 июля, а каталожная цена не включает доставку и страхование.
Чистые электромобили физлиц требуют расчёта совокупного таможенного платежа и в
режиме «только пошлина» получают статус `UNSUPPORTED`. Неоднозначные ветки ТН
ВЭД получают `MANUAL_REVIEW`, а не приблизительную сумму.

Расчётное ядро также содержит ставки 8702 и 8704 для обычных автобусов и
грузовых автомобилей, ввозимых юридическими лицами: бензин, дизель и чистая
электрическая тяга. Учитываются полная масса, объём двигателя и возрастные
границы 3, 5 и 7 лет. Гибридные ветки требуют подтверждённого соотношения
мощности ДВС и 30-минутной мощности электродвигателя, поэтому пока возвращают
`MANUAL_REVIEW`. Массовая команда сначала запускает версионированный
классификатор и только для статуса `CLASSIFIED` выбирает тарифную ветку;
неоднозначные и неполные данные сохраняются как безопасный отказ.

Версия правил `RU-EAEU-2026-01-22-v2` основана на официальных ставках
[для товаров личного пользования](https://eec.eaeunion.org/upload/medialibrary/48d/754bnati3u804penijmb0h866e5g6cng/Prilozhenie-2_107.pdf)
и [группе 87 ЕТТ ЕАЭС](https://eec.eaeunion.org/comission/department/catr/ett/ru.2022/ru.87_2022_22.01.2026.pdf).
Курсы загружаются из [ежедневного XML Банка России](https://www.cbr.ru/scripts/XML_daily.asp).

### Автоматическое обновление курсов

Celery beat ежедневно в 08:00 по часовому поясу `Europe/Moscow` ставит задачу
проверки официальных курсов CNY и EUR. Время можно изменить через
`CBR_RATES_UPDATE_HOUR` и `CBR_RATES_UPDATE_MINUTE`.

Задача получает курс за текущий и предыдущий день. При первом запуске либо при
изменении номинала или значения хотя бы одной валюты она запускает полный
перерасчёт таможенных платежей и после его успешного завершения обновляет
таблицу `cbr_exchange_rates`. Поэтому неудачный перерасчёт будет повторён
Celery, а курс не будет ошибочно отмечен как применённый. При неизменившихся
курсах записи и расчёты не обновляются. Повторный запуск задачи без изменения
курса безопасен.

Celery использует Redis как брокер. Логи планировщика и worker:

```bash
make celery-logs
```

## Локальный словарь

Общие переводы характеристик и значений находятся в
`autohome/data/translations_ru.json`. Автомобильные имена вынесены отдельно:

- `brand_names.json` — официальные международные названия брендов;
- `series_names.json` — официальные или общепринятые названия серий;
- `vehicle_name_suffixes.json` — устойчивые обозначения версий (`Classic`,
  `New Energy`, `Sport` и другие);
- `spec_name_fragments.json` — повторяющиеся обозначения комплектаций и
  коммерческих исполнений.

Полное название серии имеет приоритет перед заменой отдельных фрагментов.
Если автомобильного имени нет в словарях, исходный китайский текст сохраняется
без изменений.

Pipeline применяет словарь ко всем новым нормализованным данным. Исходный
`raw_json` остаётся китайским. Числа с единицами `万`, `万元`, `万公里` и `亿`
нормализуются программно, например `14.18万` превращается в `141800`.

Для перевода данных, сохранённых до подключения словаря, сначала остановите
парсер, затем выполните:

```bash
make translate-db
```

Команда изменяет существующие нормализованные поля пакетами. Неизвестные строки
остаются без изменений.
